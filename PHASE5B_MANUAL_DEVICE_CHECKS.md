# Phase 5B — remaining manual device checks

Browser emulation and desktop GPU rendering do not verify these conditions on physical devices.

- iPhone Safari and Android Chrome: actual touch rotate/pinch, scroll outside the canvas, browser address-bar resizing, safe-area inset and keyboard opening. Check that the sticky price/actions do not obscure the cake or focused fields.
- Low-powered phones: sustained frame rates, heat, battery usage, context loss/resume, memory after repeated tier/finish/decorations edits, and mobile DPR=1 quality. Desktop Intel GPU results are not phone performance results.
- Physical laptop/desktop touchpad and touch screen: pinch/wheel sensitivity, zoom bounds, orbit damping and reset with large square three-tier cakes.
- Firefox and Safari/WebKit: browser engines not installed in this environment. Run their Playwright projects after installing supported binaries, then inspect native date/select/color pickers and image decoding on real devices.
- VoiceOver, TalkBack and NVDA: full customer form journey, collapsed accordion announcements, drawer focus, price updates, field errors and textual 3D configuration. Automated Axe checks are not complete screen-reader verification.
- Manual colour/visual review: buttercream grain, fondant edges, ganache gloss, flower proportions, corner pearl/drip attachment and pale-colour plaque readability on calibrated screens.
- Browser clipboard denied/private modes: automatic copy and selectable fallback; OS print dialogue, printer output, page breaks and reference-image quality. Playwright checks button invocation and print CSS, not physical printing.
- Offline and slow/mobile networks: local sample photos should work; Google Fonts and other remaining illustrative about/catering photos can require internet. Check fallback typography and image-failure states.
- User-owned existing data: manually reopen an existing saved design and historical quotation in the ordinary browser, without resetting data. Automated tests use fresh isolated contexts only. Review the explicitly disclosed in-memory form draft behaviour on refresh; the cake itself survives refresh in the current tab via session storage.
- Confirm accessibility visually at 200%/400% browser zoom, operating-system text scaling and forced-colour modes. The requested viewport matrix does not replace those checks.

No physical-device, complete screen-reader, cross-engine or printer verification is claimed.
